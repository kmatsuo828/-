# 仕入先価格表の取り込み

メール添付やドライブ上の価格表を、ポータルの商品マスタに入る形まで落とす。

## 全体の流れ

```
① 資料を特定  → ② 手元に持ってくる → ③ 中身を読む
             → ④ 売値を計算      → ⑤ CSV出力 → ⑥ 価格ルール登録
```

---

## ① 資料を特定する

Gmail を `search_threads` で検索し、`get_message` で添付ファイル名を確認する。

```
from:<担当者アドレス> has:attachment newer_than:90d
(価格表 OR 価格改定 OR 新価格) newer_than:150d
```

ドライブ側にも先に当たること。**メールを探す前にドライブを見れば済むことが多い。**
`価格表` フォルダ配下、および `title contains 'メーカー名'` で全体検索する。

---

## ② 手元に持ってくる（ここが環境で分かれる）

**Gmail MCP に添付ダウンロードの RPC は無い。** `get_message` が返すのは
ファイル名・ID・MIME タイプだけで、実データは取得できない。これは仕様であり、
再確認しても結果は変わらない。

### Claude in Chrome MCP がある場合（Coworkデスクトップ等）

`gmail-attachment-organizer` と同じ要領。ログイン済み Chrome で Gmail を開き、
添付の「ドライブに保存」を押す → マイドライブ直下に落ちる → Drive MCP で
検索して所定フォルダへ移す。

### Claude in Chrome MCP が無い場合（クラウド実行）

コンテナ内の Chromium では代替できない。`mail.google.com` `drive.google.com` とも
プロキシで遮断されており、Google のログインセッションも無い。

**この場合は、その場で「できない」と伝えたうえで次のどちらかを依頼する。
黙って別の成果物に切り替えないこと。**

1. Gmail の添付から「ドライブに追加」→ `価格表/{メーカー名}/` に保存してもらう
2. 会話に直接アップロードしてもらう

保存さえされれば、以降の読み取りはクラウド実行でも問題なく通る。

---

## ③ 中身を読む

まず `read_file_content` を試す。

**テキストが壊れている／数字が化けている場合はスキャンPDF。** その場合は
`download_file_content` で base64 を取得し、画像化して目視で読む。
OCR結果をそのまま転記すると桁や記号を誤る（`¥700`→`W700`、`RDWA-70`→`ROWA-70` 等）。

```python
import json, base64, fitz   # pip install pymupdf
d = json.load(open(TOOL_RESULT_PATH))          # {content, mimeType, title}
open('src.pdf','wb').write(base64.b64decode(d['content']))
doc = fitz.open('src.pdf')
for i, pg in enumerate(doc):
    r = pg.rect                                 # 表が細かいときは上下に分割して拡大
    for j, clip in enumerate([fitz.Rect(r.x0, r.y0, r.x1, r.y0+r.height*0.55),
                              fitz.Rect(r.x0, r.y0+r.height*0.45, r.x1, r.y1)]):
        pg.get_pixmap(dpi=200, clip=clip).save(f'p{i+1}_{j+1}.png')
```

生成した PNG を Read で開いて転記する。dpi=200・上下分割で表組みはほぼ確実に読める。

**転記したら必ず検算する。** 価格表に掛率欄があるなら `仕切 ÷ 定価` が
その値と一致するかを全件チェックし、外れた品番を洗い出して原因を確認する
（掛率欄が空欄の品目は個別価格なので不一致で正常）。

## ④ 売値を計算する

ポータルの価格ルール（`zaiko-kanri.html` の `DEFAULT_PRICE_RULES`）に従う。

| メーカー | ルール |
|---|---|
| 因幡電工 | `SD-` 接頭辞（本体）＝定価55%／`SW- SJ- SK- SC- SKF- SF- SP-`（付属品）＝定価60% |
| バクマ工業 | 全製品 定価45%（AD/RDタイプ・エアコン用部材とも） |
| ルームエアコン | 定価あり→`仕入＋定価×3%`／オープン価格→`仕入×1.1`、いずれも千円未満切上 |

**定価がオープン価格（定価なし）の品目には定価基準の掛率を適用できない。**
売値は空欄のままにして、対象品番を一覧で報告する。勝手に推定した定価を入れない。

未登録メーカーの掛率は**必ず確認してから**使う。推測した掛率で売値を出さない。

## ⑤ 一括登録CSVを出力する

ポータルの 📁 商品の一括登録 →「価格も同時に登録」ON で貼れる形式。

```csv
メーカー,ジャンル,型番,に,ほ,5番,6番,自社,定価,仕入値,売値
バクマ工業,配管・部材,AD-6,0,0,0,0,0,3070,1075,1382
```

- 列は `メーカー, ジャンル, 型番, に, ほ, 5番, 6番, 自社, 定価, 仕入値, 売値`
- 在庫数の5列は `0` 埋め。定価なしは `0`、売値未定は空欄
- 文字コードは UTF-8 BOM 付き（Excel で開いたときの文字化け防止）

---

## ⑥ 価格ルールを登録する

そのメーカーのルールが `DEFAULT_PRICE_RULES` に無ければ追加し、実ブラウザで
検証してから commit する。**メーカー名を必ず指定する**こと。接頭辞だけだと
他社の同じ接頭辞（例：ネグロス電工の `SD-CV30NSY`）に誤適用される。

検証はローカル配信 + Playwright で行う。

```bash
npx http-server . -p 8899 -s &
# chromium: /opt/pw-browsers/chromium-1194/chrome-linux/chrome
# page.evaluate 内で _prBestCalc({name, maker, category, teika, cost}) を叩いて掛率を確認
```

`loadPriceRules` は Supabase → localStorage → 既定値 の順で読むため、既に保存済みの
利用者には新しい既定ルールが届かない。`_prMergeNewDefaults` が未取込分のみ追記する
（削除済みルールは `price_rules_seen_v1` に記録され復活しない）。

## 保存先フォルダ

```
マイドライブ/…/価格表/
  ├── 因幡電工/
  ├── バクマ工業/
  └── ルームエアコン/
```

無ければ `create_file` に `mimeType: application/vnd.google-apps.folder` で作る。

## 詰まったときの原則

- **制約は必ず実際に叩いて確かめる。** 「たぶん使えない」で報告しない。
  ブラウザ・ネットワーク・ツールの有無は 1 コマンドで確認できる
- **できないと分かったら、代替に走る前にその場で伝える。**
  特に見積書を XLSX で作り直すような成果物の差し替えをしない
- 制約は最初にまとめて洗い出す。詰まるたびに小出しにしない
