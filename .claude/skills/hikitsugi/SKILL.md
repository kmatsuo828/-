# セッション引き継ぎ

**引き継ぎは「メモを書く」ことではなく「次のセッションが即座に動ける状態を渡す」こと。**
下記4点を必ず全部そろえる。1つでも欠けたら引き継ぎは未完了とみなす。

1. 引き継ぎメモ（`docs/引き継ぎ_YYYYMMDD.md`）
2. **次セッションにそのまま貼れるプロンプト**
3. **環境の事前確認を指示する一文**
4. 成果物のコミット＆プッシュ

---

## 手順

### ステップ1: 現状を確定させる

- `git log --oneline` でこのセッションのコミットを洗い出す
- 未コミットの成果物（CSV・データ・スクリプト）を `docs/` に入れてコミットする。
  **スクラッチ領域に置いたままにしない。** 次セッションからは見えない
- セッションの実行環境を確認する（`get_session` の `environment_kind` / `origin`）

### ステップ2: 引き継ぎメモを書く

`docs/引き継ぎ_YYYYMMDD.md` に、この順で書く。

```
# 引き継ぎメモ（YYYY-MM-DD）
作業ブランチ／どこへ引き継ぐか／なぜ引き継ぐか

## 1. いま何が終わっていて、何が残っているか
   終わったことの表 ＋ 残タスクの箇条書き（優先度順）

## 2. 最優先タスク
   対象の特定情報（メールなら件名・差出人・受信日時・添付名まで）
   手順を番号付きで
   確定している数値・ルール
   やってはいけないこと（推定で埋めない 等）

## 3. 完了分の詳細
   出所・検算方法・件数・例外

## 4. コミット一覧
   ハッシュと内容の表 ／ 未デプロイなら明記

## 5. 環境の違い
   何が使えて何が使えないかの対比表

## 6. 次セッションへの申し送り
   このセッションでの失敗と、繰り返さないための注意
```

### ステップ3: 次セッション用プロンプトを作る（省略禁止）

**メモを渡すだけでは引き継ぎにならない。** 相手はコピペするだけで始められること。
チャットに出すだけでなく、引き継ぎメモの末尾にも同じものを載せる。

3つに分けて出す。

**(a) 環境の事前確認** — 冒頭に必ず付ける

```
作業前に、使える環境を実際に叩いて確認し、結果を先に報告してください。
（Claude in Chrome の有無、Googleドライブ連携、外部サイトへの到達可否など）
できないことが判明したら、代替手段に切り替える前に必ず知らせてください。
```

**(b) 本命タスク** — リポジトリ・ブランチ・引き継ぎメモの場所を明示し、
最優先タスクを番号付き手順で。特定情報（ファイル名・ID・日付）は省略せず全部書く。
「やってはいけないこと」も入れる。

**(c) 続けて出す用** — 余力があるとき用の残タスク。

### ステップ4: 渡す

- `docs/` 配下をコミットして push
- 引き継ぎメモと主要な成果物ファイルを `SendUserFile` で送る
- チャット本文にも (a)(b)(c) のプロンプトをコードブロックで貼る

---

## 書き方の原則

- **特定情報を省略しない。** 「佐々木様のメール」ではなく
  「件名 `RE: INABA DENKO` / `daiki.sasaki@inaba.co.jp` / 2026-07-22 8:24 /
  添付 `因幡電工　価格表　０８６.xlsx`」まで書く。次セッションは探し直しから始まる
- **数値とルールは根拠つきで書く。** 掛率なら誰がいつ確定したか、
  定価なら出所のファイル名まで
- **やってはいけないことを明記する。** 推定値で埋めない、勝手に成果物を差し替えない等。
  引き継ぎ先が同じ失敗を繰り返す
- **未デプロイ・未反映は必ず書く。** コミット済み＝反映済みではない
- **自分の失敗を隠さない。** 申し送りに書く。次が同じ穴に落ちる
